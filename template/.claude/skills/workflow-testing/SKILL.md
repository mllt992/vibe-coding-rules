# 工作流 104 · 功能测试（跑功能，不读代码）

## 触发后立即执行

1. **Read 完整工作流**：`docs/10_工作流程/104_测试工作流程.md`（开头有「分工速查」对照 103）。
2. **确认介入时机**（决定本次做什么）：
   - 需求/方案阶段 → §3 可测性评审
   - 方案设计完成 → §4 用例设计
   - 代码开发完成 → §5 自测 + §6 业务实测自检
   - PR 合并前 → §7 回归 + §8 缺陷登记
3. **触发与豁免**：
   - 100/101/102 开发完成 → 必跑（**且在 103 之后**）
   - 纯文档/注释变更 → 免跑，提交说明标 `[no-test]`
   - DB 结构变更 / 公共组件变更 → 必跑 + 全仓影响排查

## 测试分层（每一层不能互相替代）

| 层 | 目标 | 主导 |
|---|---|---|
| L1 单元 | 单函数纯逻辑分支 | AI + 开发自审 |
| L2 组件/服务 | 服务协作 / 组件渲染 | AI + 开发 |
| L3 接口契约 | REST 入参 / 出参 / 错误码 / 权限 | **AI 主导** |
| L4 集成 | 跨模块（MQ / 缓存 / 微服务） | 开发 + 测试 |
| L5 E2E | 用户视角关键业务流 | 测试 |
| L6 验收 | 产品/业务方确认 | 产品 |

> **覆盖率底线**：核心业务逻辑 L1 ≥ 70%；每接口至少 1 条 L3 happy path；金额/日期/权限相关方法 **100% 覆盖边界**。
> 覆盖率不是目标，**关键路径都被跑过**才是。

## 关键卡点

- **方案设计完成 → 用例缺失不进入编码**
- **代码开发完成 → §6 业务实测自检任何"否"必须先解决再交付**
- **BUG 修复 → 必须新增回归用例**到 `docs/05_回归用例/` 永久保留
- **PR 合并前 → 有未关闭 P0/P1 不合并**

## §6 业务实测自检速记（全部是"跑过"才能勾）

### 验收与业务流（核心义务）
- 验收用例 100% 跑过
- 主流程端到端实跑
- 至少一条异常分支实跑
- 相似功能一并验证（防"修一处漏十处"）

### 权限实测
- 构造非所有者请求断言 403
- 导出绕权实测
- 换角色登录看菜单/按钮可见性
- **响应里真实查看**是否脱敏

### 并发与一致性实测
- 并发提交断言一次成一次败
- 连续点提交按钮断言只产生一条
- MQ 重投断言下游数据不重复
- 触发失败路径断言事务回滚

### 边界与异常实测
- 空值 / null / "" / 0 / [] 实测
- 超长字段上限实测
- 1w+ 行大数据量实测
- 慢网络 / 断网实测
- 外部依赖失败实测

### 前端交互实测
- 三态（加载/空/错误）实际触发看 UI
- 响应式实际打开各分辨率
- 键盘导航实测
- Console 跑完无红错、无未捕获 Promise rejection

## AI 生成测试的强制约定（§9）

1. 命名清晰：`should_<行为>_when_<前置条件>`
2. 独立可乱序：自带数据准备与清理
3. 明确断言：**禁止仅断言"没抛异常"**
4. 真实数据源：禁止依赖生产 dump；用工厂方法 / Builder
5. Given/When/Then 结构
6. 涉及 DB 用**真实数据库**（容器化），禁止方言不同的内存 DB 模拟
7. **禁止哑测**：只为凑覆盖率、`assertNotNull(result)` 的空壳测试

> 测试代码本身写得好不好（命名/断言/结构）由 103 审查；本节是 AI 生成测试时必须遵守的硬性约定。

## PR Test plan 模板

```markdown
## Test plan
- [ ] 单元测试：xxx 模块新增/修改 N 条，覆盖率 NN%
- [ ] 接口测试：POST /api/v1/xxx happy + 4xx + 权限场景
- [ ] 验收用例：需求 §N.M 全部 X 条已跑过
- [ ] 手工烟测：登录 → 进入 X 页面 → 执行 Y → 校验 Z
- [ ] 权限实测：构造非所有者请求断言 403
- [ ] 边界实测：空数据 / 超长 / 大数据量
- [ ] 回归：相邻模块 A、B 主流程跑通
- [ ] 数据迁移：在 vX.Y 快照库执行成功，无锁等待 > 1s
- [ ] §6 业务实测自检逐条通过
```
