# 工作流 102 · BUG 修复

## 触发后立即执行

1. **Read 完整工作流**：`docs/10_工作流程/102_BUG修复工作流程.md`。
2. **任务定级**（CLAUDE.md §2），向用户报级别。涉及资金 / 鉴权 / 生产数据修复 → **高风险**。
3. **铁律自检**：根因不明、修复策略影响面大的 → 必须先问再做。
4. **多意图检测**：用户说"修个 BUG 顺便加字段 / 顺便优化" → **强制拆分串行**，BUG 修复禁止顺手扩范围。

## 关键卡点（不读原文也要先记住）

- **步骤 (1) 不能复现 = 不能修**：
  - ✅ 稳定复现 → 进入根因定位
  - ⚠️ 偶发 → 先列怀疑场景、加日志/埋点、用户确认后再继续；**不靠猜修**
  - ❌ 完全不能复现且无证据 → **暂停**，回去问开发者要更多信息（截图、日志、时间点、用户 ID）
- **步骤 (2) 根因定位思考路径**：
  1. 数据问题 vs 逻辑问题？（一条 vs 所有）
  2. 前端 vs 后端？（看 Network 面板）
  3. 单模块 vs 跨模块联动？
  4. **是否有相似代码同样有问题？grep 一遍**
- **步骤 (3) 影响范围大的 BUG**：必须收到开发者明确确认才动手；涉及**生产数据修复**必须明确"可以执行 SQL"。
- **步骤 (5) 同类 grep 必做**：根因如果是"忘了某种判断"，全仓搜相似代码一并修。

## 红线

- ❌ 修复时**顺手优化无关代码** → 增加回归风险
- ❌ 用**注释掉代码**当作"修" → 要删就删
- ❌ 用 **try/catch 吞掉错误**当作修复 → 根因要解决
- ❌ 临时日志 / 调试代码未清理就提交
- ❌ 写数据修复 SQL 不先 SELECT 验证范围就 UPDATE
- ❌ 不加回归用例 → 违反硬性要求

## 永远禁止省略

无论 BUG 多小，下列不能省：
- (2) 根因定位（哪怕一句话结论）
- (5) 同类排查
- 新增一条回归用例到 `docs/05_回归用例/`

## 任务等级速判

| 级别 | 判定 | 走法 |
|---|---|---|
| 小 BUG | 边缘场景 / 单用户 / 文案 | (1)(3) 简化为简短说明，**(2) 根因 + (5) 同类排查 + 回归用例不能省** |
| 标准 / 高风险 | 资金 / 鉴权 / 关键路径 / 多用户 / 已影响生产 | 完整流程 + 强制开发者预审 + 必做回归 + 回滚预案 |

## 前置增强（如适用，先走再回来）

- BUG 修复涉及 DB 字段变更 → 先走 [workflow-db-change](../workflow-db-change/SKILL.md) (1)~(3)
