# 工作流 101 · 已有功能优化升级

## 触发后立即执行

1. **Read 完整工作流**：`docs/10_工作流程/101_已有功能优化升级工作流程.md`。
2. **任务定级**（CLAUDE.md §2），向用户报级别。
3. **铁律自检**：不确定先问、标准/高风险必须方案确认后再动手。
4. **优化类型预判**（4 类风险点不同）：
   - 性能优化 → 风险：改 SQL / 缓存 / 异步可能引入数据一致性问题
   - 体验优化 → 风险：UI 改动影响用户已养成习惯
   - 功能增强 → 风险：兼容老数据 / 老接口调用方
   - 技术重构 → 风险：行为等价性最难证明，最易出回归
5. **多意图检测**：夹带新功能、BUG → 强制拆分串行。

## 关键卡点（不读原文也要先记住）

- **步骤 (2) 现状深度分析是这个工作流的核心**：
  - **必产物：调用方清单**（grep 全仓搜接口路径 / 函数名 / 表名 / 组件名）
  - **没做调用方清单 = 没做现状分析**，红线
  - 只看了一两个文件就开始写方案 = 不合格
- **步骤 (4) 影响评估卡点**：结构化呈现"改了什么 / 影响什么 / 是否数据迁移 / 是否分批 / 灰度 / 最坏回滚"，明确确认后才开发。
- **步骤 (6) 回归视角**：受影响调用方全跑、历史用例库全跑、新增"防撞坏"用例。
- **优化的最大风险是破坏原有行为**——回归测试不是可选项。

## 红线

- ❌ 在优化中**顺手扩展功能** → 把功能扩展拆成独立任务进 100
- ❌ **清理无关代码** → 本任务专注本任务
- ❌ **性能优化无 before/after 数据** → 不算数
- ❌ **重构改变了外部行为** → 行为变化属功能升级，拆出去
- ❌ **DB 字段直接删** → 先停止写入，留兼容期再删
- ❌ 兼容期代码无清晰删除日期标记

## 任务等级速判

| 级别 | 判定 | 走法 |
|---|---|---|
| 微改动 | 改文案 / 单行 | 本工作流不适用 |
| 小任务 | 单模块小幅调整 | (1)(2)(3) 可合并为简短"变更说明"，**步骤 (6) 三视角自审 + 回归不能省** |
| 标准 / 高风险 | 多模块 / 含 DB / 含接口契约变更 / 公共组件 | 完整流程 |
