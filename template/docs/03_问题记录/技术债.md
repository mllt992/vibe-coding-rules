# 技术债清单

> 记录代码中**已知但暂未处理**的问题。
>
> **不写 = 永远遗忘 = 永远不修。**
> 凡是 AI 在任务过程中遇到的"范围外但发现的问题"，**禁止顺手改**，记录到此处。

---

## 使用规则

1. 任何"应该处理但本次不处理"的问题进入此清单
2. 每条必含：发现日期、模块、问题、为何不修、影响、修复优先级
3. 状态：`待处理` / `已计划` / `已修复` / `已确认不修`
4. 定期评审（建议每月）：高优先级条目排期；过期条目按规则关闭或重排

---

## 优先级

| 等级 | 含义 | 处置 |
|---|---|---|
| P1 | 严重风险，已对生产构成隐患 | 1 个月内必修 |
| P2 | 影响开发效率或可维护性 | 排入下次迭代 |
| P3 | 代码异味，无即时影响 | 顺手可改时改 |

## 关闭一条债务时

- 在状态写"已修复"，备注 PR 链接
- 不要直接删除条目——保留历史便于回溯
- 如果决定永久不修，状态写"已确认不修"+ 原因
