# 03 · 问题记录

> 本目录存放 BUG 记录、技术债务、待处理问题。

---

## 内容分类

| 子分类 | 命名 | 用途 |
|---|---|---|
| BUG 记录 | `yyyymmdd_BUG_<问题描述>.md` | 每个 BUG 一个文件，按 BUG 修复工作流处理 |
| 技术债 | `技术债.md` | 集中归档暂不处理但应记录的代码异味 / 历史包袱 |
| 临时问题 | `yyyymmdd_TODO_<问题>.md` | 暂时记录、待决策、不属于 BUG 的待办 |

---

## 文档来源

- BUG：复制 `docs/20_模板/BUG记录模板.md`
- 技术债：直接追加到 `技术债.md`（见该文件的格式）
- 样例：`docs/20_模板/_示例_BUG记录_xxx.md`

---

## BUG 记录的生命周期

1. 报告 → 状态 `待复现`
2. 复现成功 → `已复现`
3. 分析根因 → 写入 §7
4. 修复方案 + 确认 → `修复中`
5. 提交修复 → 自审 + 回归 → `已修复`
6. 验证通过 → `已关闭`
7. 不予处理 → `不处理`（理由必写）

---

## 重要约定

- **每个 BUG 修复必须产出回归用例**，拷贝到 `docs/05_回归用例/`，永久保留
- **同根因影响多处时**：在同一文档列出所有受影响位置，**禁止拆成多份 BUG 单**导致失联
- 技术债条目要写"为什么不修"，避免变成永久遗忘
