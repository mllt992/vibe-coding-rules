# 04 · 代码审查报告

> 本目录存放每次代码审查的报告文档。

---

## 命名规则

```
yyyymmdd_审查_<功能或PR简称>.md
```

例：
- `20260513_审查_用户角色管理.md`
- `20260520_审查_PR#142_订单导出.md`

---

## 何时写报告

按 `103_代码审查工作流程.md` 的规则：
- ✅ 必写：新功能开发（100）、优化升级（101）、BUG 修复（102）的开发完成后
- ✅ 必写：超过 200 行变更的 PR
- ⚠️ 可省：微改动（typo / 改文案 / 单行修复）—— 在 PR 描述中写一两句即可，不必单独建文件

---

## 文档来源

复制 `docs/20_模板/代码审查报告模板.md`，填写后归档到此目录。

参考样例：`docs/20_模板/_示例_代码审查报告_xxx.md`

---

## 报告的去向

- 报告中阻断项 → 作者修复后再次审查
- 报告中重要项 → 视情况决定本次修还是排期
- 审查通过 → 报告中"结论"标注通过；PR 可合并
- 报告中发现的新规范缺口 → 同步更新对应 `docs/00_通用规范/` 文档
