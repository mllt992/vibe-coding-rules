# 前端页面开发规范

> 适用范围：基于 Vue VBen Admin 5.x 的前端工程 `vue-vben-admin`，业务应用聚焦 `apps/web-antd`。
> 与本文档配套阅读：`API接口设计规范.md`、`页面_列表页设计规范.md`、`页面_表单页设计规范.md`、`组件_*` 系列。

---

## 1. 工程总体定位

| 维度 | 选择 |
|------|------|
| 框架 | Vue 3 + `<script setup>` + TypeScript |
| 工程化 | pnpm workspace + Turborepo monorepo（VBen Admin 5.7.0） |
| UI 库 | Ant Design Vue（business app 默认 `web-antd`） |
| 状态 | Pinia（业务 store 在 `apps/web-antd/src/store`，公共 store 来自 `@vben/stores`） |
| 路由 | Vue Router 4，动态路由由后端菜单驱动 |
| 表单 | `@vben/common-ui` 的 `useVbenForm` + `VbenFormSchema` |
| 表格 | `@vben/plugins/vxe-table` 的 `useVbenVxeGrid` |
| 请求 | `@vben/request` 封装的 `RequestClient` |
| 国际化 | `@vben/locales` + `$t()` |
| 构建 | Vite |

## 2. monorepo 与目录约定

```
vue-vben-admin/
├── apps/
│   ├── web-antd/              # 业务应用（本规范主战场）
│   └── backend-mock/          # 仅本地联调 Mock
├── packages/
│   ├── @core/                 # 框架运行时核心，禁止业务侵入
│   ├── effects/               # 通用业务效果（access、layouts、common-ui ...）
│   ├── stores/                # 公共 store（access、user、tabbar ...）
│   ├── locales/               # 国际化基础设施
│   ├── preferences/           # 全局偏好（accessMode、defaultHomePath ...）
│   └── icons / styles / types / utils / constants
└── playground/                # 框架联调示例，**不要参考其代码作为业务范式**
```

**业务代码原则上只允许放在 `apps/web-antd/src` 下；** 如确需通用化（多 app 共享），再下沉到 `packages/effects` 或自建业务 package。

## 3. `apps/web-antd/src` 目录规范

```
src/
├── main.ts / bootstrap.ts        # 启动入口，禁止改动
├── app.vue / preferences.ts      # 应用根 + 偏好覆盖
├── api/
│   ├── request.ts                # 全局 RequestClient（鉴权、拦截器、错误处理）
│   ├── core/                     # 平台级 API：auth / user / menu / ...
│   └── {domain}/                 # 业务域 API（按后端模块拆分）
├── adapter/
│   ├── component.ts              # 组件枚举与 props 映射

│   └── routes/
│       ├── core.ts               # 登录/403/404 等核心路由
│       └── modules/{domain}.ts   # 静态路由模块（导航/壳路由），动态权限路由由后端下发

├── views/
│   ├── _core/                    # 框架自带页面（authentication、fallback、profile）

└── locales/                      # 应用级文案
```

### 业务子目录命名

- 域名 `{domain}` 与后端模块对齐：`user`、`org`、`role`、`permission`、`workflow`...；
- 页面文件夹 `{page}` 用 kebab-case：`user-list`、`user-form`、`role-detail`；
- 入口文件统一 `index.vue`；同目录可放 `components/`、`composables/`、`schema.ts`、`columns.ts`。

## 4. API 层规范

所有后端调用必须经过 `apps/web-antd/src/api/request.ts` 暴露的 `requestClient`：

- 协议字段：`code` / `data` / 成功码 `200`，与后端 `Result<T>` 严格对齐；
- 鉴权：请求拦截器自动注入 `Authorization: Bearer {accessToken}`，token 来自 `useAccessStore`；
- 401 / token 失效：`authenticateResponseInterceptor` 自动触发刷新或重登录；
- 业务错误（`code != 200`）：默认 `message.error` 提示，可在调用处 `try/catch` 自定义。

### API 文件结构

```ts
// src/api/user/index.ts
import { requestClient } from '#/api/request';

export namespace UserApi {
  export interface ListParams { keyword?: string; status?: number; page: number; size: number }
  export interface UserItem { id: number; username: string; ... }
}

export function listUsersApi(params: UserApi.ListParams) {
  return requestClient.get<PageResult<UserApi.UserItem>>('/users', { params });
}

export function createUserApi(data: UserApi.CreateParams) {
  return requestClient.post<number>('/users', data);
}
```

**约束：**
- 一个 namespace 对应一个后端模块的所有接口；
- 入参/出参必须显式声明 TypeScript 类型，禁止 `any`；
- 后端字段命名差异（如 `token` ↔ `accessToken`）在 API 层一次性映射，store/页面不感知；
- **不允许**在组件内直接 `axios` 或 `fetch`。

## 5. 路由与权限规范

### 5.1 三种 accessMode（由 `preferences.app.accessMode` 决定）

| 模式 | 路由表来源 | 适用 |
|------|-----------|------|
| `frontend` | 前端静态 + `meta.authority` | 简单系统 |
| `backend` | 后端 `getAllMenusApi` 返回 | **本系统默认** |
| `mixed` | 前端基础 + 后端补充 | 过渡期 |

### 5.2 静态 vs 动态路由

- 静态：`router/routes/core.ts` + `routes/modules/*.ts`，承载 layout、登录页、错误页、强制可见的工作台；
- 动态：登录后由 `generateAccess` 调用 `getAllMenusApi` 拉取，组件路径通过 `import.meta.glob('../views/**/*.vue')` 解析；
- **后端菜单返回的 `component` 字段必须能被前端 glob 命中**，路径与 `src/views/{domain}/{page}/index.vue` 对齐。

### 5.3 Meta 字段（`RouteMeta`）

| 字段 | 用途 |
|------|------|
| `title` | 必填，使用 `$t('page.xxx.title')` |
| `icon` | iconify 图标名 |
| `authority` | 角色码数组（前端模式） |
| `affixTab` | 固定 Tab |
| `ignoreAccess` | 公开页（不校验登录） |
| `keepAlive` / `hideInMenu` / `order` | 按需 |

### 5.4 守卫

- 守卫定义在 `router/guard.ts`，**业务侧禁止再注册全局 `beforeEach`**；
- 业务级权限校验通过 `meta.authority` + 角色码、或在 store 中提供 `hasPermission(code)` 方法供组件调用。

---

## 6. 状态管理（Pinia）

- 一个域一个 store 文件；命名 `use{Domain}Store`，id 与文件名一致；
- 推荐 setup 风格 `defineStore('xxx', () => { ... })`；
- 通用账户/权限 store 来自 `@vben/stores`：`useAccessStore`、`useUserStore`，**不要重复实现**；
- **禁止**在 store 中直接调用 `requestClient`，由 store 调用 `api/` 模块封装的方法；
- 登出 / 重置：登出走 `useAuthStore.logout`；切租户/重新登录前必须 `resetAllStores()`。

## 7. 页面开发规范（结合既有子规范）

### 7.1 通用结构

每个业务页面 `index.vue` 推荐结构：

```vue
<script setup lang="ts">
import { Page } from '@vben/common-ui';
import { useVbenVxeGrid } from '#/adapter/vxe-table';
import { columns } from './columns';
import { searchSchema } from './schema';
import { listUsersApi } from '#/api/user';

const [Grid, gridApi] = useVbenVxeGrid({
  formOptions: { schema: searchSchema, collapsed: true },
  gridOptions: {
    columns,
    proxyConfig: {
      ajax: { query: ({ page }, formValues) =>
        listUsersApi({ ...formValues, page: page.currentPage, size: page.pageSize })
      },
    },
  },
});
</script>

<template>
  <Page auto-content-height>
    <Grid />
  </Page>
</template>
```

### 7.2 列表页

遵循 `页面_列表页设计规范.md` 与各组件规范：

- 搜索区：使用 `formOptions`，多于一行需可折叠并将折叠态缓存（VBen 已默认 42h 持久化）；下拉支持模糊搜索，日期范围支持快捷预设（本周/本月/本季/本年）；
- 表格：`useVbenVxeGrid`；表头冻结、操作列固定、数字右对齐、表头标题居中；
- 行内/工具栏操作：高危操作（删除）必须二次确认 `Modal.confirm` 并展示影响范围；
- 分页协议：`{records, total, page, size}` ↔ vxe-table 的 `proxyConfig.response = { result: 'records', total: 'total' }`（如不一致，在适配器或调用处转换）；
- 导出：每个列表页**必须**接入 `组件_导出组件要求.md` 规定的能力（按筛选条件、自定义字段、字段排序、文件名 `YYYY年M月D日{标题}.xlsx`）。
- 时间/日期格式化：统一使用 `@vben/utils` 的 `formatDateTime` / `formatDate`（基于 dayjs，含时区与无效值兜底），见 `组件_表格组件要求.md`；**禁止**业务页自行 `replace/slice` 或额外引入 `dayjs/moment` 仅为格式化。

### 7.3 表单页

遵循 `页面_表单页设计规范.md`：

- 使用 `useVbenForm` + `VbenFormSchema`，统一 label 位置、必填红星、错误提示；
- 必填校验通过 `defineRules` 已注册的 `required` / `selectRequired`；
- 提交按钮在 loading 期间禁用；后端业务错误（`code != 200`）由 `requestClient` 默认提示，复杂场景在调用处 `try/catch` 接管；
- 编辑回填：先 `gridApi.setLoading(true)`，请求详情接口后 `formApi.setValues()` 再关闭 loading；
- 取消按钮触发"未保存提示"。

### 7.4 详情页 / 抽屉

- 简单详情用 `Drawer` 内嵌只读 `useVbenForm`（`disabled` 模式）；
- 复杂详情独立路由 `views/{domain}/{page}-detail/index.vue`，通过 `query.id` 取参；
- 多 Tab 详情页使用 `a-tabs`，懒加载子组件。

## 8. 表单 / 表格适配器规范

### 8.1 form.ts

- 在 `setupVbenForm` 中维护 `modelPropNameMap`（如 `Switch: 'checked'`）；
- 公共校验规则在 `defineRules` 注册一次，业务页面用 `rules: 'required'` 引用，**禁止在每个 schema 重写正则**。

### 8.2 vxe-table.ts

- 全局 `gridOptions`（border、columnConfig、proxyConfig、size）在 `configVxeTable` 内集中定义，**业务页面只覆写差异项**；
- 自定义渲染器（`CellImage`、`CellLink`、`CellTag` 等）统一在适配器注册，业务页面 `cellRender: { name: 'CellXxx' }` 引用；
- `proxyConfig.response` 必须与后端分页协议保持单一来源，避免每个页面再映射。

## 9. 国际化与文案

- 所有静态文案必须 `$t('xxx')`，禁止硬编码中文/英文；
- 业务文案放在 `apps/web-antd/src/locales/langs/{lang}/{domain}.json`，命名空间与目录对齐；
- 框架级文案来自 `@vben/locales`（`common.*`、`ui.*`），禁止覆盖。

---

## 10. 样式与主题

- 优先使用 Tailwind 原子类（已配置 `@vben/tailwind-config`）；
- 复杂样式写 `<style scoped>`，避免全局污染；
- **禁止**直接修改 `@core` / `effects` 中的样式；如需调整，通过 `preferences.theme` 或 CSS 变量覆盖；
- 暗色 / 亮色主题已由框架处理，自定义颜色必须用 CSS 变量（`var(--color-primary)`）。

---

## 11. 代码质量与提交

- 类型：`pnpm check:type`；循环依赖：`pnpm check:circular`；依赖完整性：`pnpm check:dep`；拼写：`pnpm check:cspell`；
- Lint：`pnpm lint`（oxlint + eslint），格式：`pnpm format`（oxfmt + stylelint）；
- 提交：`pnpm commit`（czg + commitlint），分支策略与后端一致；
- lefthook 已配置 pre-commit / pre-push 钩子，禁止 `--no-verify` 跳过。

---

## 12. 反模式（禁止清单）

- ❌ 业务组件内 `axios.create` / 直接 `fetch`；
- ❌ 在 `views/` 中定义可复用 hooks（应放 `composables/` 或下沉到 `packages/effects`）；
- ❌ 写死 API 路径（缺少 namespace 封装）；
- ❌ 直接修改 `packages/@core` 或 `playground/`；
- ❌ `any` / `as unknown as Xxx` 强转，必须给出真实类型；
- ❌ 重复实现 `useUserStore` / `useAccessStore`；
- ❌ 在 setup 顶层 `await` 写阻塞逻辑（应放 `onMounted` 或 `<Suspense>`）；
- ❌ 路由 meta 中放置可变状态；
- ❌ 列表页直接用 `a-table` 自行分页（必须经 `useVbenVxeGrid`，否则与全局规范偏离）；
- ❌ 跳过国际化、跳过导出能力；
- ❌ 业务页面手写 `replace('T',' ').slice(0,19)` 或重复封装时间格式化（统一 `@vben/utils` 的 `formatDateTime`）。
