## 1. 现象描述

- **现象**：用户访问受保护页面（如 `/orders/12345`）被引导到登录页（URL 为 `/login?redirect=%2Forders%2F12345`），登录成功后**跳到了首页 `/`**，没有跳回 `/orders/12345`
- **截图**：附件 `bug-001-redirect.png`
- **错误信息**：无前端 Console 报错；接口返回 200 正常

1. 未登录状态打开浏览器
2. 访问 `https://app.example.com/orders/12345`
3. 自动跳转到 `https://app.example.com/login?redirect=%2Forders%2F12345`
4. 输入正确凭证，点击"登录"
5. 观察跳转目标

**前置数据**：任意有效用户（如 `testuser`）
**环境**：Chrome 125 / 测试环境

## 7. 根因分析

### 7.1 排查过程
- 检查点 1：登录接口返回值 → 正常，包含 token
- 检查点 2：路由器拿到 redirect 参数 → 通过 console.log 确认 `route.query.redirect` 为 `/orders/12345` ✓
- 检查点 3：跳转代码 `router.push(redirect || '/')` → 这里看似正确
- 检查点 4：跳转**之前**的代码 → **发现** `await store.dispatch('user/login', ...)` 之后**还有一个 `await router.replace('/')`** 在更早的代码路径中遗留
- 检查点 5：grep `router.replace.*'/'` → 找到 `LoginPage.vue:87` 残留的硬编码跳转，写在 `else` 分支但实际会被异步执行触达

### 7.2 根因结论

`LoginPage.vue:79-92` 的登录成功处理中：
```js
const success = await login(form)
if (success) {
  const redirect = route.query.redirect as string
  await router.push(redirect || '/')   // 正确逻辑
}
await router.replace('/')              // ← 这一行漏在条件外，永远执行，覆盖了上面的跳转
```

`router.replace('/')` 在 if 块**外面**，每次都执行；且因为 `router.replace` 比 `router.push` 后执行，导致最终落到 `/`。

### 7.3 触发条件
- 任意：登录成功 + redirect 参数非空

### 7.4 为什么之前没发现
- **代码视角**：开发者重构时把 `else` 分支删了但忘记一起删后面的兜底 `router.replace`
- **测试视角**：TC-AUTH-001 测的是"无 redirect 直接登录"，未覆盖"带 redirect 登录"——**测试用例覆盖不足**
- **上线视角**：QA 当时按主用例验收，未做"未登录访问深链"场景

### 7.5 相似代码排查
- grep `router.replace.*'/'`：还有 `LogoutPage.vue:34` 一处，是退出后回首页，逻辑正确，**不需要改**
- grep `router.push.*redirect`：仅本处
- **未发现其他相似问题**

## 8. 修复方案

### 8.1 修复策略
- [x] **直接修复**：删除遗留的 `router.replace('/')`，让条件内的跳转生效

### 8.2 具体改动
`LoginPage.vue:88`：删除一行 `await router.replace('/')`

```diff
   const success = await login(form)
   if (success) {
     const redirect = route.query.redirect as string
     await router.push(redirect || '/')
   }
-  await router.replace('/')
```

### 8.3 可能的副作用
- 几乎无副作用——原 `router.replace` 行为已被条件内的 `router.push` 完全覆盖
- 唯一变化：登录失败时不再"被强制踢回首页"，停留在登录页（**这其实是更正确的行为**）

### 8.4 数据修复
- 不涉及
