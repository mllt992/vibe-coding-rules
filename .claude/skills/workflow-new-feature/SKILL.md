# 工作流 100 · 新功能开发

## 触发后立即执行

1. **Read 完整工作流**：`docs/10_工作流程/100_新功能开发工作流程.md`，按其步骤执行。原文档是单一信息源，本 skill 只承担"触发 + 关键警示"。
2. **任务定级**：参照 `CLAUDE.md §2` 给本任务定级（微改动 / 小 / 标准 / 高风险），用一句话向用户报告级别及理由。**定级有疑问就高不就低**。
3. **铁律自检**（CLAUDE.md §1）：
   - 业务规则 / 字段含义 / API 契约 / 权限规则有不确定 → **先问再做**，禁止瞎猜
   - 标准 / 高风险任务**必须先出方案**，得到"开始 / 确认 / 同意 / 可以"等明确字眼才动代码；"嗯""哦""知道了"**不算**
4. **多意图检测**：用户同时夹带"BUG / 优化 / 加字段 / 改原型"等意图时，**强制拆分串行**，不要一锅炖。

## 关键卡点（不读原文也要先记住）

- **步骤 (3) 方案确认是硬卡点**：方案以结构化摘要形式发，主动提争议点和影响范围；得到明确确认才进入开发。
- **步骤 (4) 开发铁律**：每动一个领域的代码前**再读一遍对应规范**（`docs/00_通用规范/`），禁止"先跑通再说"——跑通后不会回来补。
- **边写边跑**：禁止整批代码写完才第一次运行/编译。
- **步骤 (5) 自审三视角**：代码视角 / 业务视角 / 回归视角（同模式代码 grep 一遍）。

## 任务等级速判

| 级别 | 判定 | 走法 |
|---|---|---|
| 微改动 | typo / 改文案 / 单行调整 | **本工作流不适用**，直接做 |
| 小任务 | 单模块、< 100 行、无 DB / 接口契约变化 | 跳过 (1)(2) 需求与方案文档，仍走自审 + 测试 |
| 标准 | 新功能 / 多模块 / 含 DB 或接口契约变更 | **完整流程**，全部归档 |
| 高风险 | 资金 / 鉴权 / DB 迁移 / 公共组件 / 跨服务 | 标准 + 强制开发者预审 + 必做回归 + 回滚预案 |
