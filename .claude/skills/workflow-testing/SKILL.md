# 工作流 104 · 测试

## 触发后立即执行

1. **Read 完整工作流**：`docs/10_工作流程/104_测试工作流程.md`。
2. **确认介入时机**（决定本次做什么）：
   - 需求/方案阶段 → §3 可测性评审
   - 方案设计完成 → §4 用例设计
   - 代码开发完成 → §5 自测 + §6 自检清单
   - PR 合并前 → §7 回归 + §8 缺陷登记
3. **触发与豁免**：
   - 100/101/102 开发完成 → 必跑
   - 纯文档/注释变更 → 免跑，提交说明标 `[no-test]`
   - DB 结构变更 / 公共组件变更 → 必跑 + 全仓影响排查

## 测试分层（每一层不能互相替代）

| 层 | 目标 | 主导 |
|---|---|---|
| L1 单元 | 单函数纯逻辑分支 | AI + 开发自审 |
| L2 组件/服务 | 服务协作 / 组件渲染 | AI + 开发 |
| L3 接口契约 | REST 入参 / 出参 / 错误码 / 权限 | **AI 主导** |
| L4 集成 | 跨模块（MQ / 缓存 / 微服务） | 开发 + 测试 |
| L5 E2E | 用户视角关键业务流 | 测试 |
| L6 验收 | 产品/业务方确认 | 产品 |

> **覆盖率底线**：核心业务逻辑 L1 ≥ 70%；每接口至少 1 条 L3 happy path；金额/日期/权限相关方法 **100% 覆盖边界**。
> 覆盖率不是目标，**关键路径都被测过**才是。

## 关键卡点

- **方案设计完成 → 用例缺失不进入编码**
- **代码开发完成 → 自检清单（§6）任何"否"必须先解决再交付**
- **BUG 修复 → 必须新增回归用例**到 `docs/05_回归用例/` 永久保留
- **PR 合并前 → 有未关闭 P0/P1 不合并**

## 自检清单速记（§6 高频项）

### 数据与边界
- 日期范围开闭区间 SQL / 后端 / 前端三端一致
- 小数 ↔ 百分比转换只发生一次
- 金额后端高精度 + 序列化字符串 + 前端千分位
- 分页 page 起始（0 / 1）前后端一致
- 排序带 ID 作为 tiebreaker
- 空值 / 超长 / 大数据量场景明确

### 权限与安全
- 功能权限 + **数据权限在 SQL 层**（不是 Service 内存过滤）
- 字段脱敏在序列化层
- 构造非所有者请求断言 403
- 后端二次校验，**禁止仅依赖前端校验**
- 日志禁止打印明文密码 / token / 身份证 / 手机号

### 并发与一致性
- 写入有乐观锁或唯一索引，模拟并发断言
- 跨表写入同一事务；**外部 HTTP/MQ 调用不卷入数据库事务**
- 消费者幂等

### 前端交互
- 三态齐全（加载 / 空 / 错误）
- 浏览器 Console 无红错、无未捕获 Promise rejection
- 导出与列表当前筛选条件一致

## AI 生成测试的强制约定（§9）

1. 命名清晰：`should_<行为>_when_<前置条件>`
2. 独立可乱序：自带数据准备与清理
3. 明确断言：**禁止仅断言"没抛异常"**
4. 真实数据源：禁止依赖生产 dump；用工厂方法 / Builder
5. Given/When/Then 结构
6. 涉及 DB 用**真实数据库**（容器化），禁止方言不同的内存 DB 模拟
7. **禁止哑测**：只为凑覆盖率、`assertNotNull(result)` 的空壳测试

## PR Test plan 模板

```markdown
## Test plan
- [ ] 单元测试：xxx 模块新增/修改 N 条，覆盖率 NN%
- [ ] 接口测试：POST /api/v1/xxx happy + 4xx + 权限场景
- [ ] 手工烟测：登录 → 进入 X 页面 → 执行 Y → 校验 Z
- [ ] 回归：相邻模块 A、B 主流程跑通
- [ ] 数据迁移：在 vX.Y 快照库执行成功，无锁等待 > 1s
- [ ] 自检清单（§6）逐条通过
```
