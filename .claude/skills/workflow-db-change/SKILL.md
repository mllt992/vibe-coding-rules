# 工作流 106 · 数据库变更（前置增强 + 默认高风险）

## 与 100 / 101 / 102 的关系

**前置增强，不替代**：
- 新功能 + DB 变更 → 先走 106 (1)~(5)，再回 [workflow-new-feature](../workflow-new-feature/SKILL.md)
- 已有功能改造 + DB 变更 → 先走 106 (1)~(5)，再回 [workflow-refactor](../workflow-refactor/SKILL.md)
- BUG 修复涉及 DB 字段 → 先走 106 (1)~(3)，方案确认后并入 [workflow-bug-fix](../workflow-bug-fix/SKILL.md)

## 触发后立即执行

1. **Read 完整工作流**：`docs/10_工作流程/106_数据库变更工作流程.md`。
2. **任务定级**：**DB 变更默认高风险**（CLAUDE.md §2 已明确）。
   - 例外可降为标准：只新增 COMMENT / 只改字典枚举值（不涉结构）/ 只加纯辅助索引（小表）
   - **强制高风险**：涉及主表、跨服务表、金额表、鉴权表
3. **核心认知**：**数据是项目最稳定也最难变更的部分**。偷懒的字段或没演练的迁移会在三个月后让全员加班。

## 关键卡点（不读原文也要先记住）

- **步骤 (2) 留痕设计是核心产物**：复制 `docs/20_模板/数据库变更设计模板.md` 到 `docs/02_功能设计/数据库变更/yyyymmdd_xx变更_设计.md`，**逐节填写不留空**。
- **步骤 (3) 跨角色对齐六视角签字 ⚠️ 硬卡点**：
  - 任何角色"待确认" → **不进入 (4) 写迁移**
  - 高风险变更未经 DBA 评审 → 不进入 (4)
  - 涉及 PII 未经安全 / 合规评审 → 不进入 (4)
  - 跨服务表未通知下游 owner → 不进入 (4)
  - "嗯""知道了" → 不算确认
- **步骤 (5) 演练**：演练失败或耗时超预期 → 回 (4) 调整，**不允许上线**；演练未覆盖 down → **不允许上线**

## 六视角对齐（步骤 3 核心）

| 视角 | 关键问题 |
|---|---|
| 🏛 架构师 | 这表归谁？演进路径？跨服务影响？ |
| 🗄 DBA | 容量？锁？索引？迁移耗时？回滚？ |
| 💻 开发 | ORM / 接口 / 类型 / Mock 怎么改？ |
| 📋 PM | 风险？跨团队？发版顺序？回滚预案？ |
| 🧪 软件工程 | 留痕完整吗？追溯链通吗？ |
| 📊 数据 | 血缘？报表影响？PII？合规？ |

## 红线（违反 = 工作未完成）

- ❌ **未出设计文档就写迁移 SQL** → 留痕缺失
- ❌ **字段无中文 COMMENT** → 违反 `03_数据库设计规范.md §三补`
- ❌ **跨角色对齐表有"待确认"就开工**
- ❌ **没演练就上生产** → DB 变更是单向门
- ❌ **没有 down 脚本** → 出问题只能硬上，无回滚能力
- ❌ **直连生产 DB 改结构** → 跳过迁移工具 = 无审计 / 无版本 / 无重放
- ❌ **PII 字段不脱敏 / 不加密 / 不标记** → 合规风险
- ❌ **跨服务表变更不通知下游** → 隐式破坏契约
- ❌ **设计文档与迁移文件不互链** → 信息黑洞
- ❌ **大表 ALTER 直接一步到位**（应分步）
- ❌ **数据回填没 LIMIT 没事务保护**

## 发布顺序（步骤 7）

| 变更类型 | 顺序 |
|---|---|
| 加字段 / 加索引（兼容性） | **先迁移 → 再发代码** |
| 删字段 / 改类型（破坏性） | **先发代码停止使用 → 观察 → 再迁移删除** |
| 数据回填 | **迁移到位后单独执行**，不卷入应用发布 |

观察期至少 **1 周**：慢查询 / 错误日志 / 业务指标 / 下游消费方报告。

## 关键迁移规则

- 所有字段含**中文 COMMENT**（PII 字段含标记）
- 大表 ALTER 走分步（见 `03_数据库设计规范.md §七`）
- 数据回填脚本：带 `LIMIT` / 分批 / 幂等 / 事务保护
- **同步写 down 脚本**（或显式"不可回滚"声明 + 理由）
- 每个迁移文件头部含"关联设计: docs/02_功能设计/数据库变更/xxx.md"

## 一定要记住的反直觉

- **"只是加个字段"是最容易掉以轻心的场景**：默认值 / 空值 / 回填 / 下游同步任一项漏了都可能炸
- **"先改 DB 后想起来更新字典"** → 字段语义变更必须**同批次**
- **"等会儿手动 INSERT 一行测试数据"** → 走迁移文件，不要在控制台 hack
- **回滚脚本要真测**（演练必须包含 down），不要只写不验
