# 工作流 105 · 原型协同开发（前置增强）

## 与 100 / 101 的关系

**前置增强，不替代**：
- 新功能 + 原型 → 先走 105 (1)~(5)，再回到 [workflow-new-feature](../workflow-new-feature/SKILL.md) 的测试 / 审查 / 归档
- 已有功能改造 + 原型 → 先走 105 (1)~(5)，再回到 [workflow-refactor](../workflow-refactor/SKILL.md) 的回归与测试

## 触发后立即执行

1. **Read 完整工作流**：`docs/10_工作流程/105_原型协同开发工作流程.md`。
2. **任务定级**（CLAUDE.md §2），向用户报级别。
3. **核心认知**：原型会撒谎——它用 mock 数据回避空/错/加载态，用独立样式回避设计系统，用静态页回避状态机/路由/权限。**直接照搬 = 后期返工**。

## 关键卡点（不读原文也要先记住）

- **步骤 (2) 三方对齐是本流程价值所在**：逐页面把原型 / PRD / 现有代码库三栏对照，不一致 / 缺失 / 矛盾全部摆到台面让开发者拍板。
- **卡点规则**：
  - ❌ 差异 / 缺口清单未产出 → 不进入 (3) 拆解映射
  - ❌ 清单中"待澄清"项未关闭 → **不进入开发**
  - ❌ 开发者只说"嗯""知道了" → **不算确认**
  - ✓ "按这个清单做"等明确字样 → 进入下一步

## 三类必查的"缺口"

- **A. PRD 要而原型没画**：错误态文案 / 无权限态 / 空数据态 / 超长截断 / 加载骨架 / 移动端布局 / 表单校验提示
- **B. 原型暗示而 PRD 没写**：hover 效果 / 跳转目标 / 确认弹层文案 / 键盘交互（Enter 提交 / Esc 取消）/ 列表排序默认 / 图标含义
- **C. 当前系统没有，需新建 / 改造**：新接口 / 新字段 / 新菜单 / 新权限点 / 新组件变体 / 新枚举值

## 重点检查项（容易漏）

- 空态 / 加载态 / 错误态 / 无权限态（**四态**）每页都明确
- 移动端 / 响应式断点行为
- 表单：必填 / 长度 / 格式 / 异步校验 / 错误回显位置 / 提交防重
- 数据权限：列表过滤了，详情 / 导出 / 编辑也要过滤
- 跳转目标：返回上一页 vs 返回列表 vs 关闭弹层
- 国际化：原型里的中文文案是否需走 i18n
- 字典 / 枚举：原型上的标签是否对应系统字典

## 红线

- ❌ **还没出差异 / 缺口清单就动代码** → 跳过等于没走 105
- ❌ **像素级复刻原型但绕开设计系统**：硬编码 `#fff` / `font-size: 16px` / `margin: 24px`
- ❌ **用原型的 mock 数据结构当接口契约** → 接口契约由后端 + API 规范主导
- ❌ **只实现原型画了的态**，忽略空 / 错 / 无权限 / 加载
- ❌ **原型用的第三方组件 / 图标 / 字体直接引入** → 先查项目已有依赖
- ❌ **原型与 PRD 冲突时自己拍板** → 必须停下问开发者

## 分层落地（步骤 4，禁止一口气糊出来）

| 层 | 做什么 | 自查 |
|---|---|---|
| 1. 静态骨架 | 设计令牌堆骨架 + 假数据按真实接口形态 | 与原型并排布局一致 / 无硬编码颜色字号 / 仅用表 A 标注的组件 |
| 2. 接真实数据 | 真接口 / 路由 / 状态机 / 表单校验 | PRD 验收主流程跑通 / Console 无红错 / Network 无 4xx-5xx |
| 3. 边缘态 | 四态 / 权限 / 国际化 / 响应式 | 对照交付前自检清单 §7 + §4 全勾 |

## 任务等级速判

| 级别 | 走法 |
|---|---|
| 微改动（改文案 / 改颜色一处） | 本工作流不适用 |
| 小任务（改原型一个小片段、< 100 行、无接口变更） | 走 (2) 三方对齐 + (3) 拆解映射，跳过 (5) 双轨验收归档 |
| 标准 / 高风险 | 完整走 |
