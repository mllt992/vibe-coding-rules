### 3.1 表清单

### 3.2 新建表 DDL（含中文注释）

> **每个字段必须有中文 COMMENT**。COMMENT 写"业务含义 + 取值范围/枚举来源 + 是否 PII"，不要只写字段英文名的中文直译。

```sql
-- 表 coupon_redemption · 优惠券核销记录
-- 设计依据：docs/02_功能设计/数据库变更/20260513_优惠券核销表_设计.md
-- 数据归属：营销域 / marketing-svc

CREATE TABLE coupon_redemption (
  id           BIGINT       NOT NULL  COMMENT '主键，雪花 ID',
  coupon_id    BIGINT       NOT NULL  COMMENT '优惠券 ID，外键 coupon.id',
  order_id     BIGINT       NOT NULL  COMMENT '订单 ID，外键 order_main.id',
  user_id      BIGINT       NOT NULL  COMMENT '核销用户 ID；PII 关联，导出需脱敏',
  redeem_at    TIMESTAMP    NOT NULL  COMMENT '核销时刻，UTC，业务确认时间',
  amount_cent  BIGINT       NOT NULL  COMMENT '核销抵扣金额，单位"分"，禁止用 FLOAT',
  channel      VARCHAR(32)  NOT NULL  COMMENT '核销渠道，枚举 REDEEM_CHANNEL（见系统字典）',
  status       VARCHAR(32)  NOT NULL  DEFAULT 'success'
                                      COMMENT '核销状态，枚举 REDEEM_STATUS（success/refunded/disputed）',
  is_deleted   BOOLEAN      NOT NULL  DEFAULT FALSE
                                      COMMENT '软删除标记',
  created_at   TIMESTAMP    NOT NULL  DEFAULT CURRENT_TIMESTAMP
                                      COMMENT '记录创建时间',
  updated_at   TIMESTAMP    NOT NULL  DEFAULT CURRENT_TIMESTAMP
                                      COMMENT '记录最后更新时间',
  created_by   BIGINT       NULL      COMMENT '创建人 user_id；系统写入则为 NULL',
  updated_by   BIGINT       NULL      COMMENT '最后更新人 user_id',
  CONSTRAINT pk_coupon_redemption PRIMARY KEY (id),
  CONSTRAINT uk_coupon_redemption_coupon_order
             UNIQUE (coupon_id, order_id)
             /* 一张券对同一订单只能核销一次，业务唯一性兜底 */
);

COMMENT ON TABLE coupon_redemption IS '优惠券核销记录，记录每次核销动作及抵扣金额';

CREATE INDEX idx_coupon_redemption_user_redeem_at
       ON coupon_redemption (user_id, redeem_at DESC);
-- ↑ 支撑"按用户查最近核销"高频查询；范围字段放后

CREATE INDEX idx_coupon_redemption_order
       ON coupon_redemption (order_id);
-- ↑ 财务对账按订单反查
```

### 3.3 改表 DDL（如有）

```sql
-- 订单主表新增"已用优惠券"汇总字段
ALTER TABLE order_main
  ADD COLUMN coupon_discount_cent BIGINT NOT NULL DEFAULT 0
             COMMENT '订单累计优惠抵扣金额，单位"分"，由核销服务回写';
```

> ⚠️ 大表加非空字段必须按 `03_数据库设计规范.md` §七"危险操作的安全做法"分步走，本节直接写最终态，分步过程写到 §6 迁移脚本。

### 3.4 字段语义详表（**给开发 / 数据 / 业务三方看**）

| 字段 | 类型 | 中文名 | 业务含义 | 取值范围 / 枚举来源 | PII | 数据来源 | 下游使用 |
|---|---|---|---|---|---|---|---|
| `coupon_redemption.amount_cent` | BIGINT | 抵扣金额（分） | 本次核销实际抵扣金额 | ≥ 0；上限同优惠券面值 | 否 | 核销服务写入 | 财务报表、用户手册 |
| `coupon_redemption.user_id` | BIGINT | 核销用户 | 关联 user.id | 系统中存在的用户 ID | **关联 PII** | 核销服务写入 | 日志脱敏、导出脱敏 |
| `coupon_redemption.channel` | VARCHAR(32) | 渠道 | 核销发生在哪个端 | `REDEEM_CHANNEL` 字典（web/h5/ios/android/admin） | 否 | 核销服务写入 | BI 报表分渠道统计 |

> PII 列填 "是" / "否" / "关联 PII"（自身不是但能拼出用户身份）。这一列直接决定后续脱敏策略。

## 6. 迁移 SQL 与回滚

### 6.1 迁移文件清单

> SQL 物理位置以 [`CLAUDE.md §0`](../../CLAUDE.md) "项目基本情况"中声明的路径为准（项目层一次性约定）。

| 序号 | 文件名 | 内容摘要 |
|---|---|---|
| 1 | `V20260513001__create_coupon_redemption.sql` | 建表 + 索引 + COMMENT |
| 2 | `V20260513002__add_order_main_coupon_discount.sql` | 订单表加字段（带默认值） |
| 3 | `V20260513003__backfill_order_coupon_discount.sql` | 老订单回填 |

### 6.2 迁移内容要点

- [ ] 所有 DDL 写入迁移文件，**禁止直连生产改结构**
- [ ] 迁移文件**只增不改**（已发布的不允许修改，要改加新版本）
- [ ] DDL 含完整 COMMENT（中文注释强制项）
- [ ] 大表 ALTER 走分步：可空字段 → 回填 → NOT NULL
- [ ] 数据回填脚本带 `LIMIT` 或分批，避免长事务
- [ ] 文件头注释含"设计文档路径"（双向链接）

### 6.3 回滚脚本

> **每个迁移必须有对应的 down 脚本或显式 "不可回滚" 声明 + 理由**。

```sql
-- Down: V20260513001__create_coupon_redemption.sql
-- 风险：建表后若已有写入，DROP 会丢数据。回滚前先确认写入量 = 0。

DROP INDEX IF EXISTS idx_coupon_redemption_order;
DROP INDEX IF EXISTS idx_coupon_redemption_user_redeem_at;
DROP TABLE IF EXISTS coupon_redemption;
```

### 6.4 回滚预案（上线后回滚的完整步骤）

1. 停止应用对新表 / 新字段的写入（开关：xxx）
2. 检查写入量、备份当前数据
3. 跑 down 脚本（顺序与 up 相反）
4. 验证：xxx 查询能正常工作
5. 通知下游消费方

### 6.5 不可回滚项（如有）

- 字段 xxx 加 NOT NULL 后无法直接回滚为 NULL（数据已变更），回滚需先回填默认值再回滚
