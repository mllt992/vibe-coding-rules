## 1. 背景与问题（为什么要做）

- **当前问题 / 业务诉求**：财务团队每月对账时，需要把"订单实付金额"和"使用的优惠券抵扣"对得上。当前订单表只记了 `total_cent`（实付），没记优惠券信息，对账靠从营销侧 `coupon_redemption` 反向 join，每月人工补 ~2 人日。
- **不做会怎样**：财务对账持续手工补数；BI 优惠券 ROI 报表口径不准（仅能看核销表，无法做"使用券的订单"维度的下钻）；监管审计要求"订单凭证完整"无法满足。
- **为什么用 DB 变更解决而非代码层**：报表 join 关键路径，必须落到列上才能走索引；历史订单需可追溯，不能仅靠应用层关联表查。
- **替代方案与放弃原因**：曾考虑"应用层每次查询时 join 核销表" —— 性能差（订单详情页 P99 +80ms），且大数据量报表 join 不可控。

## 3. 表与字段设计

### 3.1 表清单

| 操作 | 表名 | 业务概念（中文） | 数据归属 | 预估行数（当下） | 年增长率预估 |
|---|---|---|---|---|---|
| 改表 | `order_main` | 订单主表 | 交易域 / order-svc | 800w | 30% |

### 3.2 改表 DDL

```sql
-- 阶段 1：加可空字段（不阻塞写入）
ALTER TABLE order_main
  ADD COLUMN coupon_id BIGINT NULL
       COMMENT '订单使用的优惠券 ID，外键 coupon.id；NULL 表示未使用优惠券',
  ADD COLUMN coupon_discount_cent BIGINT NOT NULL DEFAULT 0
       COMMENT '优惠券抵扣金额，单位"分"，≥0，禁止 FLOAT；未使用券时为 0',
  ADD COLUMN coupon_status VARCHAR(32) NULL
       COMMENT '优惠券使用状态，枚举 ORDER_COUPON_STATUS（applied/refunded/disputed），NULL 表示未使用券';

-- 阶段 2：加索引（财务对账高频查询）
CREATE INDEX idx_order_main_coupon_id
       ON order_main (coupon_id)
       WHERE coupon_id IS NOT NULL;  -- PG 部分索引；MySQL 直接全表
```

> 注：原计划 `coupon_discount_cent` 设为 NOT NULL，因 800w 老数据无法在线加 NOT NULL，分两步走（先 DEFAULT 0 + 回填后再考虑约束加固）。详见 §6。

### 3.3 字段语义详表

| 字段 | 类型 | 中文名 | 业务含义 | 取值范围 / 枚举来源 | PII | 数据来源 | 下游使用 |
|---|---|---|---|---|---|---|---|
| `order_main.coupon_id` | BIGINT NULL | 优惠券 ID | 本订单使用的优惠券，关联 `coupon.id` | 关联存在的优惠券 ID，或 NULL | 否 | 下单时由 order-svc 写入；核销完成回写 | 财务对账、BI 报表、订单详情 API |
| `order_main.coupon_discount_cent` | BIGINT NOT NULL | 抵扣金额（分） | 本订单优惠券实际抵扣金额 | ≥ 0；上限同优惠券面值；未用券为 0 | 否 | 下单时由 order-svc 写入 | 财务对账、用户手册"优惠抵扣"展示 |
| `order_main.coupon_status` | VARCHAR(32) NULL | 券使用状态 | 用券订单的券状态，便于退款/纠纷处理 | `ORDER_COUPON_STATUS`（`applied` / `refunded` / `disputed`），未用券为 NULL | 否 | order-svc 写入；退款时由 finance-svc 更新 | 财务对账、客服系统 |

### 5.2 查询性能

- **新增 / 改动的高频查询模式**：
  - Q1: `SELECT * FROM order_main WHERE coupon_id = ?` —— 财务对账反查
  - Q2: `SELECT order_id, coupon_discount_cent FROM order_main WHERE created_at BETWEEN ? AND ?` —— BI 报表
  - Q3: `SELECT * FROM order_main WHERE user_id = ? AND coupon_id IS NOT NULL ORDER BY created_at DESC` —— 用户用券订单列表
- **每条查询命中的索引**：
  - Q1 → 新建 `idx_order_main_coupon_id`
  - Q2 → 复用现有 `idx_order_main_created_at`
  - Q3 → 复用现有 `(user_id, created_at)` 复合索引，`coupon_id IS NOT NULL` 走过滤
- **慢查询基线**：当前 Q1（反向 join 实现）P99 = 350ms；改造后预计 P99 = 30ms（演练实测 28ms）

### 5.3 锁与可用性

- **DDL 是否锁表**：☒ 否（PG 11+ 加可空字段 + 默认值不重写表，元数据级操作）
- **使用的在线 DDL 方式**：☒ PG 原生（加可空字段 + DEFAULT 不重写表）
- **预估变更耗时**：< 1 秒（演练实测 300ms）

#### 文件 V20260513003 回填脚本（节选）

```sql
-- 变更主题: 回填老订单优惠券字段
-- 关联设计: docs/02_功能设计/数据库变更/20260513_订单加优惠券字段_设计.md
-- 关联需求: docs/01_需求分析/20260510_优惠券对账需求.md
-- 风险等级: 高风险
-- 作者 / 日期: 张三 / 2026-05-13
-- 回滚脚本: V20260513003__backfill_order_main_coupon.down.sql

DO $$
DECLARE
  batch_size INT := 10000;
  affected INT;
BEGIN
  LOOP
    UPDATE order_main o
    SET coupon_id = r.coupon_id,
        coupon_discount_cent = r.amount_cent,
        coupon_status = 'applied'
    FROM coupon_redemption r
    WHERE o.id = r.order_id
      AND o.coupon_id IS NULL
      AND o.id IN (
        SELECT o2.id FROM order_main o2
        JOIN coupon_redemption r2 ON o2.id = r2.order_id
        WHERE o2.coupon_id IS NULL
        LIMIT batch_size
      );
    GET DIAGNOSTICS affected = ROW_COUNT;
    EXIT WHEN affected = 0;
    PERFORM pg_sleep(0.1);
  END LOOP;
END $$;
```

### 6.3 回滚脚本

```sql
-- Down: V20260513001__add_order_main_coupon_fields.sql
-- 风险：删字段后已写入的优惠券关联数据将丢失，回滚前必须备份。

ALTER TABLE order_main
  DROP COLUMN IF EXISTS coupon_status,
  DROP COLUMN IF EXISTS coupon_discount_cent,
  DROP COLUMN IF EXISTS coupon_id;
```
