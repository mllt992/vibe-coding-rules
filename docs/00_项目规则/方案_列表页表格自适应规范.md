# 列表页表格自适应规范方案

> 适用于基于 **Vue 3 + ant-design-vue 4.x** 的中后台列表页。
> 采用 **方案 A：Flex 高度链 + ResizeObserver 动态 `scroll.y`**。
> 目标：所有列表页在任意视口、任意菜单折叠状态、任意搜索区高度下，**表格自动填满剩余空间，分页固定底部，整页不出现滚动条**。

---

## 1. 适用范围

✅ 适用：

- 中后台标准列表页（搜索 + 工具 + 表格 + 分页）。
- 需要 **固定表头、固定列（`fixed: 'left' / 'right'`）、虚拟滚动** 的表格。
- 数据量从十几条到上万条。

❌ 不适用：

- 流式长页面（多个表格上下排列、整页滚动）。
- 表格高度需要随数据量自然伸缩的报表/打印页。

> 不适用的场景请使用普通文档流，不要套用本规范。

## 2. 页面结构与高度链

### 2.1 标准 DOM 骨架

```
html, body, #app                       height: 100%
└─ a-layout.basic-layout               height: 100vh
   ├─ a-layout-sider                   height: 100vh
   └─ a-layout (右侧)                  display: flex; flex-direction: column; height: 100vh
      ├─ a-layout-header               flex: 0 0 56px
      └─ a-layout-content              flex: 1; min-height: 0; overflow: hidden
         └─ .page                      height: 100%; display: flex; flex-direction: column
            ├─ .search-panel           flex: 0 0 auto      ← 按内容高度
            ├─ .tool-panel             flex: 0 0 auto      ← 按内容高度
            ├─ .table-panel  (ref)     flex: 1 1 auto; min-height: 0   ← 占满剩余
            └─ .pager-panel            flex: 0 0 auto      ← 按内容高度
```

### 2.2 高度链规则（**最重要**）

| 规则 | 说明 |
| --- | --- |
| **R1** | 从 `html` 到 `.table-panel`，**每一层** 都必须有显式高度或受控 flex。任一层断链则失效。 |
| **R2** | 每一级 flex 子项 **必须加 `min-height: 0`**。flex 默认 `min-height: auto` 会被内容撑开溢出。 |
| **R3** | 整页 **禁止出现垂直滚动条**。`#app { overflow: hidden }` 兜底。 |
| **R4** | 内容溢出只允许发生在 **`.table-panel` 内部**（由 a-table 接管）。 |
| **R5** | 搜索区、工具区、分页区 **不得使用 `flex: 1`**，避免抢占表格高度。 |

### 2.3 反模式（禁止写法）

```css
/* ❌ 禁止：父级没有高度，子级 flex:1 不会生效 */
.page { display: flex; flex-direction: column; }   /* 缺 height */

/* ❌ 禁止：忘记 min-height:0，表格被内容撑开整页出滚动条 */
.table-panel { flex: 1; }

/* ❌ 禁止：用百分比硬算高度，菜单折叠、视口变化都会失效 */
.table-panel { height: calc(100vh - 280px); }

/* ❌ 禁止：表格容器加 overflow:auto，会和 a-table 内部滚动打架 */
.table-panel { overflow: auto; }
```

### 3.2 复用 Hook：`useTableHeight`

> 位置：`src/composables/useTableHeight.ts`

```ts
import { onBeforeUnmount, onMounted, ref, type Ref } from 'vue'

interface Options {
  /** a-table 表头高度，默认按 middle size = 55 */
  headerHeight?: number
  /** 额外预留高度（边框/汇总行/工具条 padding 等） */
  reserved?: number
}

export function useTableHeight(
  wrapperRef: Ref<HTMLElement | null>,
  options: Options = {},
) {
  const { headerHeight = 55, reserved = 0 } = options
  const tableY = ref(0)

  let ro: ResizeObserver | null = null

  const measure = () => {
    const el = wrapperRef.value
    if (!el) return
    const rect = el.getBoundingClientRect()
    const next = Math.max(0, Math.floor(rect.height - headerHeight - reserved))
    if (next !== tableY.value) tableY.value = next
  }

  onMounted(() => {
    measure()
    if (typeof ResizeObserver !== 'undefined' && wrapperRef.value) {
      ro = new ResizeObserver(() => measure())
      ro.observe(wrapperRef.value)
    }
    window.addEventListener('resize', measure)
  })

  onBeforeUnmount(() => {
    ro?.disconnect()
    window.removeEventListener('resize', measure)
  })

  return { tableY, measure }
}
```

## 4. 参数手册

### 4.1 a-table 必填参数

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `:scroll` | `{ x: <列总宽>, y: tableY }` | y 来自 hook；x 是所有列 `width` 之和 |
| `:pagination` | `false` | 分页必须**外置**，不使用 a-table 内置分页 |
| `row-key` | 业务主键（如 `id`） | 不要用数组下标 |
| `size` | `middle`（默认） | 改 size 同时要改 `headerHeight` |

### 4.2 `headerHeight` 取值参照

| a-table `size` | headerHeight |
| --- | --- |
| `small` | **39** |
| `middle`（默认） | **55** |
| `large` | **55** |
| 多级表头（n 行） | `单行高度 × n` |
| 含筛选/排序图标但不增加行高 | 不变 |

### 4.3 `reserved` 取值参照

> 把"表头之外、占据表格容器、不能被滚动"的部分加进来。

| 元素 | 预留值 |
| --- | --- |
| 表格四周 border | 2 |
| `<a-table summary>` 汇总行（middle） | +55 |
| 表格内置 `title` slot | +47 |
| 表格内置 `footer` slot | +47 |
| 自定义工具条贴在表格顶部 | +实际高度 |

## 5. 进阶场景

### 5.1 搜索区高度动态变化（展开/收起）

❌ 不需要 hook 改写：ResizeObserver 监听的是 `.table-panel` 本身，搜索区变高 → 表格容器变矮 → 自动重测。

✅ 做法：搜索区的"展开/收起"按钮只切换 v-show / v-if，CSS 高度链会自动响应。

### 5.2 `keep-alive` 多 Tab 切换

切换 Tab 时组件被缓存而非卸载，重新激活时容器尺寸不变 → 不需要额外处理。

如有"激活时浏览器已改尺寸"的边缘情况，在 `onActivated` 里手动触发一次：

```ts
import { onActivated } from 'vue'
const { tableY, measure } = useTableHeight(wrapperRef)
onActivated(() => measure())
```

### 5.3 模态框 / 抽屉里的表格

弹层里的表格也适用本规范，只需保证弹层 body 是 flex 列容器、并给出固定 height（如 `60vh`）。

### 5.4 含汇总行 `<a-table-summary>`

```ts
useTableHeight(wrapperRef, {
  headerHeight: 55,
  reserved: 2 + 55, // 边框 + summary 行高
})
```

### 5.5 字体缩放 / 浏览器 zoom

ResizeObserver 在大多数浏览器（含 IE 不支持但中后台一般不要求）下都会对 zoom 触发。无需额外处理。

### 5.6 SSR 场景

`useTableHeight` 内部对 `ResizeObserver` 做了 `typeof` 判断，SSR 下不会报错；客户端 hydration 后 `onMounted` 中执行测量。

## 6. 伸缩列（列宽拖拽）

### 6.1 目标与适用场景

让用户用鼠标拖动表头右边缘改变列宽，**不破坏**第 2 节的高度链、固定列、横向滚动。

适用：备注/名称这类内容长短不一的列，希望用户按需放宽。
不适用：列设置弹层里"输入数字调整宽度"——那是另一种交互，本节不覆盖。

### 6.2 实现思路

ant-design-vue 没有内置 resizable 列，但开放了两个钩子：

1. **`:components.header.cell`** —— 用自定义组件替换默认 `<th>` 渲染
2. **`customHeaderCell`** —— 每一列返回一组 props，会被透传给上面的自定义组件

组合用法：自定义组件渲染 `<th>` + 右侧 6px 拖拽手柄，`mousedown` 时挂全局 `mousemove/mouseup`，把新宽度通过 `onResize` 回调上抛；composable 把回调连到响应式列宽 state，列宽变了 → `columns` 重新计算 → antd 的 `<colgroup><col>` 跟着变 → 表格立即重排。

```
ResizableHeaderCell.vue       useResizableColumns.ts            <a-table>
─────────────────────────     ──────────────────────────         ────────
渲染 <th> + 拖拽手柄          widths ref<Record<number,number>>   :columns
mousedown                     handleResize(idx, w)                :components.header.cell
 → onResize(newWidth) ───────→ widths[idx] = w                    :scroll.x = scrollX
                              columns = computed(...)             ↑
                                ├── customHeaderCell()            │
                                │     → 透传 width / onResize ────┘
                                └── width: widths[idx] ?? base
                              scrollX = computed(各列宽相加)
```

### 6.3 文件清单

| 文件 | 职责 |
| --- | --- |
| `src/components/ResizableHeaderCell.vue` | `<th>` + 拖拽手柄；处理鼠标事件、宽度边界 |
| `src/composables/useResizableColumns.ts` | 管理 `widths` 响应式状态，产出 `columns` / `scrollX` |

### 6.4 标准接入

```vue
<template>
  <section ref="tableWrapperRef" class="panel table-panel">
    <a-table
      size="middle"
      :columns="columns"
      :data-source="pagedData"
      :pagination="false"
      :scroll="{ x: scrollX, y: tableY }"
      :components="tableComponents"
      bordered
      row-key="id"
    />
  </section>
</template>

<script setup lang="ts">
import { useTableHeight } from '@/composables/useTableHeight'
import { useResizableColumns } from '@/composables/useResizableColumns'
import ResizableHeaderCell from '@/components/ResizableHeaderCell.vue'

// 1. 原始列定义：需要可拖拽的列必须有数字 width
const baseColumns = [
  { title: '订单号', dataIndex: 'id', key: 'id', width: 140, fixed: 'left' as const },
  { title: '订单名称', dataIndex: 'name', key: 'name', width: 220, ellipsis: true },
  // ...
  { title: '操作', key: 'action', width: 180, fixed: 'right' as const, resizable: false },
]

// 2. 装饰为可伸缩列。buffer 给 row-selection / 行展开等系统列预留
const { columns, scrollX } = useResizableColumns(baseColumns, { buffer: 60 })

// 3. 把自定义 <th> 注入到 a-table
const tableComponents = { header: { cell: ResizableHeaderCell } }

const tableWrapperRef = ref<HTMLElement | null>(null)
const { tableY } = useTableHeight(tableWrapperRef, { headerHeight: 55, reserved: 2 })
</script>
```

### 6.5 API

#### `useResizableColumns(initial, options?)`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `initial` | `T[]` | 原始列定义（**只读**；只用作初始值和列元信息） |
| `options.defaultWidth` | `number = 120` | 没有显式 `width` 的列在累加 `scrollX` 时的占位 |
| `options.buffer` | `number = 0` | `scrollX` 总和外再加的缓冲；用来给 row-selection、行展开图标等系统列留位置 |

返回：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `columns` | `ComputedRef<T[]>` | 装饰后的列定义，直接喂给 `<a-table :columns>` |
| `scrollX` | `ComputedRef<number>` | 各列宽实时之和，喂给 `:scroll.x` |
| `resetWidths` | `() => void` | 把所有列宽恢复成 `initial` 里的初始值 |

#### 列定义新增字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `width` | `number` | **必填**才会出现拖拽手柄（无 width 的弹性列保持原样） |
| `minWidth` | `number = 60` | 拖拽下限 |
| `maxWidth` | `number = 1200` | 拖拽上限 |
| `resizable` | `boolean = true` | 显式 `false` 时该列不出现拖拽手柄 |

### 6.6 关键规则

| 规则 | 说明 |
| --- | --- |
| **R6** | `scroll.x` **必须**用 `scrollX` 而非写死。写死会导致拖宽列后横向滚动条够不到最后一列。 |
| **R7** | 右侧 `fixed: 'right'` 的列（如"操作"）建议设 `resizable: false`，避免拖动后 sticky 偏移与剩余空间冲突。 |
| **R8** | 无 `width` 的弹性列（如带 `ellipsis` 的"备注"）不会出现拖拽手柄；它的宽度由 antd 按剩余空间分配。 |
| **R9** | 拖拽过程在 `<body>` 上加 `.col-resizing` 全局类，强制 `cursor: col-resize` 和禁用文字选中。`mouseup` 时必须清理。 |
| **R10** | 列宽 state 放在组件实例内（composable 内部 `ref`），**不要**挂到全局。多个列表页的列宽互不影响。 |

### 6.7 反模式

```ts
// ❌ scroll.x 写死。拖宽列后滚不到尾。
<a-table :scroll="{ x: 1200, y: tableY }" />

// ❌ 没给列设 width。手柄不出现，用户以为坏了。
{ title: '名称', dataIndex: 'name' }

// ❌ 直接 mutate initial 数组。Vue 不会追踪外部对象，且失去"重置"语义。
baseColumns[2].width = 200

// ❌ 在 mousemove 里 setTimeout / nextTick。拖拽要 60fps 同步反馈，任何延迟都会粘手。
```

### 6.8 持久化（按需）

如果要把用户调整后的列宽存到 localStorage / 用户设置接口：

```ts
const { columns, scrollX } = useResizableColumns(baseColumns)

// 初始化时塞回已保存的宽度
onMounted(() => {
  const saved = JSON.parse(localStorage.getItem('cols:order') ?? '{}')
  Object.entries(saved).forEach(([idx, w]) => {
    /* 直接改 widths 需要把 widths 暴露出来 —— 当前 API 没暴露，自行扩展 */
  })
})

// 当前 API 只暴露了 resetWidths；如需 setWidths 请按需在 composable 中扩展。
```

> 持久化不是默认行为。需要时再扩展 composable 暴露 `setWidths` / `widths`，避免把存储逻辑硬塞进通用 hook。

### 6.9 与方案 A / 方案 B 的关系

- **方案 A（ResizeObserver）**：已演示。`scroll.x` 用 `scrollX`，垂直高度仍由 `tableY` 控制，互不干扰。
- **方案 B（纯 Flex）**：不传 `scroll.x` 也能跑——`<colgroup><col>` 宽度变了，内层 `<table>` 自然变宽，外层 `.ant-table-content { overflow:auto }` 出横向滚动条。如果观察到滚动条到不了尾，再补 `:scroll="{ x: scrollX }"`（注意这会切换 antd 的内部布局结构，需要相应调 `:deep(...)` 选择器）。

## 7. 验收 Checklist

提交列表页 PR 前自查：

- [ ] 整页 **没有** 垂直滚动条（菜单/header 不滚动）
- [ ] 分页区**视觉**贴在视口底部，不被表格挤下去也不悬浮
- [ ] 浏览器窗口缩放、菜单折叠 → 表格高度实时跟随
- [ ] 表头固定，表体上下滚动；`fixed` 列左右固定正常
- [ ] 切换页面再回来、resize 后无白屏或抖动
- [ ] 数据为空时表格仍占满剩余空间，"暂无数据" 居中
- [ ] 数据极少（如 1 条）时表格不被压缩到 0 高度
- [ ] `headerHeight` / `reserved` 注释了取值来源
- [ ] 没有用 `calc(100vh - 任何数字px)`
- [ ] 表格容器没有写 `overflow: auto`

## 8. FAQ

**Q1：为什么不用 `calc(100vh - 280px)` 这种纯 CSS 方案？**
搜索区行数、Header 高度、是否有面包屑等都会变。硬编码 280px 一旦布局微调就全错。

**Q2：为什么要外置分页，不用 a-table 自带 `pagination`？**
内置分页位于表格滚动区内部，会随表体一起滚走；视觉上也不容易做"固定底部"。

**Q3：用方案 B（纯 CSS Flex）行不行？**
轻量列表（无 `fixed` 列、无虚拟滚动）可用；中后台业务推荐统一方案 A，减少踩坑。

**Q4：为什么 `tableY` 是 `number` 而不是字符串 `'100%'`？**
a-table 的固定表头、固定列、虚拟滚动都依赖**具体像素值**计算行高与位置。`'100%'` 会让固定列失效。

**Q5：tableY 第一次渲染是 0，会闪一下吗？**
`onMounted` 同步执行第一次 `measure`，用户基本感受不到。如有强需求可在 SSR 注水时给个默认值（如 `400`）。

## 9. 一句话总结

> **高度链一通到底 + ResizeObserver 监听容器 + `scroll.y` 喂给 a-table**，再配合外置分页，就是中后台列表页自适应的最佳实践。
