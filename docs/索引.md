## 六、按场景查表

### 我要开发新功能
1. 必读：[`100_新功能开发工作流程.md`](10_工作流程/100_新功能开发工作流程.md)
2. 模板：[`需求分析模板.md`](20_模板/需求分析模板.md) → [`实施方案设计模板.md`](20_模板/实施方案设计模板.md)
3. 相关规范：[`02`](00_通用规范/02_API接口设计规范.md)、[`03`](00_通用规范/03_数据库设计规范.md)、[`04`](00_通用规范/04_前端开发规范.md)、[`05`](00_通用规范/05_后端开发规范.md)、[`06`](00_通用规范/06_安全规范.md)
4. 完成前：[`交付前自检清单.md`](90_最佳实践/交付前自检清单.md)

### 我有原型（HTML / Figma）要落地
1. 必读：[`105_原型协同开发工作流程.md`](10_工作流程/105_原型协同开发工作流程.md)（前置）
2. 走完 105 的"三方对齐 + 拆解映射 + 分层落地 + 双轨验收"
3. 之后按是否新功能进入 [`100`](10_工作流程/100_新功能开发工作流程.md) 或 [`101`](10_工作流程/101_已有功能优化升级工作流程.md) 的测试 / 审查 / 归档
4. 重点参考前端 / 安全规范：[`04`](00_通用规范/04_前端开发规范.md)、[`06`](00_通用规范/06_安全规范.md)

### 我要修 BUG
1. 必读：[`102_BUG修复工作流程.md`](10_工作流程/102_BUG修复工作流程.md)
2. 模板：[`BUG记录模板.md`](20_模板/BUG记录模板.md)
3. 思路指引：[`通用陷阱清单.md`](90_最佳实践/通用陷阱清单.md)
4. 修复后：必新增回归用例到 [`05_回归用例/`](05_回归用例/)

### 我要审代码
1. 必读：[`103_代码审查工作流程.md`](10_工作流程/103_代码审查工作流程.md)（含"审 AI 代码特殊关注点"小节）
2. 模板：[`代码审查报告模板.md`](20_模板/代码审查报告模板.md)
3. 维度对照：[`00_通用规范/`](00_通用规范/) 各文件

### 我要写测试
1. 必读：[`104_测试工作流程.md`](10_工作流程/104_测试工作流程.md)
2. 测试用例格式：见 104 §4.3
3. 反例驱动：[`通用陷阱清单.md`](90_最佳实践/通用陷阱清单.md)
