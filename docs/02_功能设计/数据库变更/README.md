# 02 · 功能设计 / 数据库变更

> 本目录存放每次数据库变更（DDL / 大体量 DML）的设计文档。
> 与工作流 [`106 数据库变更工作流程`](../../10_工作流程/106_数据库变更工作流程.md) 配套使用。
> **设计未确认前禁止写迁移 SQL、禁止动数据库。**

---

## 何时归档到这里

任一项即触发：

- DDL：新建表 / 加字段 / 改字段类型 / 改字段长度 / 加/删/改索引 / 加/删约束 / 改默认值 / 改 COMMENT
- 大体量 DML：数据回填、清洗、迁移（影响行数 > 1w 或涉及关键业务表）
- Schema 重命名 / 移动 / 拆库拆表 / 归档 / 删表

---

## 命名规则

```
yyyymmdd_<变更主题>_设计.md
```

例：
- `20260513_订单加优惠券字段_设计.md`
- `20260520_用户表手机号加密迁移_设计.md`
- `20260601_订单表按月分区改造_设计.md`

## 与迁移文件的双向链接（强制）

- **本目录的设计文档** §6.1 "迁移文件清单"必须列出所有相关迁移文件名（含路径）
- **每个迁移 SQL 文件**头部注释必须含 `-- 关联设计: docs/02_功能设计/数据库变更/yyyymmdd_xx_设计.md`
- 两边任一处缺失 = 留痕断链 = 工作未完成

SQL 文件的物理位置见 [`CLAUDE.md §0`](../../../CLAUDE.md)（项目层一次性约定）。

---

## 与实施方案的关系

```
需求分析 → 实施方案 → 数据库变更设计 → 迁移 SQL → 开发
```

- 含 DB 变更的功能：实施方案文档简述 DB 改动思路，**详细设计落到本目录的设计文档**
- 实施方案 §3 "数据库设计"小节应引用本目录文档路径
- 纯 DB 变更（无配套功能）：可直接在本目录建文档，元信息中"关联实施方案"标"无"
