# 10 · 用户手册

> 本目录存放面向最终用户/管理员的功能使用说明。
> **不是开发者文档**——读者是产品使用者，不懂代码。

---

## 命名规则

```
yyyymmdd_<功能名>功能说明.md
```

例：
- `20260513_用户角色管理功能说明.md`
- `20260520_订单导出功能说明.md`

---

## 必含小节

每份功能说明建议包含：

1. **功能简介** —— 一段话说清楚解决什么问题、谁用、什么场景
2. **入口位置** —— 菜单路径、可见角色、需要的权限点
3. **操作步骤** —— 按操作流程编号说明，建议配截图
4. **字段说明** —— 关键字段的含义、约束、默认值、示例
5. **常见问题** —— FAQ 形式回答最容易问的问题
6. **管理员配置**（重要）—— 上线后需要管理员做的配置：
   - 菜单设置
   - 角色分配
   - 权限点分配
   - 数据权限规则
   - 字典维护

---

## 何时新增/更新

| 触发场景 | 动作 |
|---|---|
| 新功能上线 | 必须新增一份 |
| 功能优化升级，行为有变化 | 更新对应文档 |
| BUG 修复**改变了用户操作方式** | 更新对应文档 |
| 内部重构不影响用户操作 | 不必更新 |

---

## 重要约定

- **用户能看懂的语言** —— 避免代码 / 类名 / 数据库字段名
- **配截图** —— 截图是产品文档的灵魂，纯文字读不懂
- **管理员配置小节是上线 checklist** —— 不写，上线时管理员不知道该怎么配
- 文档变更同步记入 `docs/文档更新日志.md`
